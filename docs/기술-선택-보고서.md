## 1. 결론 요약

| 질문 | 답 |
|---|---|
| Chrome과 기록·쿠키·캐시·로그인 세션이 분리된 "진짜" 브라우저를 만들 수 있나? | **예.** Android 앱(Kotlin + WebView)은 Android 앱 샌드박스 안에 자기 전용 WebView 프로필을 가지므로 Chrome과 데이터를 공유하지 않습니다. 이 저장소의 APK가 그것입니다. |
| 사용자의 Chromebook(Play 스토어 X, Linux X)에서 그 APK를 설치할 수 있나? | **현재 조건 그대로는 사실상 불가능합니다.** 아래 2장 참고. |
| 웹 페이지(HTML)만으로 같은 분리를 얻을 수 있나? | **아니요.** Chrome 안에서 도는 HTML은 Chrome의 쿠키 저장소와 방문 기록을 그대로 씁니다. "브라우저처럼 생긴 HTML"은 독립 브라우저가 아니므로 완성품으로 제시하지 않았습니다. |
| 그럼 무엇을 선택했나? | **A안(Kotlin + Android WebView APK)** 을 구현하고 GitHub Actions에서 빌드·테스트·배포합니다. 설치 경로가 막힌 기기에는 **ChromeOS가 기본 제공하는 분리 수단(게스트 모드, 별도 사용자/프로필, 시크릿 창)** 과 **관리자 배포 요청**을 승인된 대안으로 제시합니다. |

## 2. 사용자 환경에서 APK 설치가 막히는 이유

ChromeOS에서 Android 앱이 실행되려면 Android 런타임(ARC++/ARCVM)이 켜져 있어야 하고, Play 스토어를 거치지 않은 APK를 설치하려면 다음 중 하나가 필요합니다.

| 설치 경로 | 필요한 것 | 사용자 환경 |
|---|---|---|
| Google Play 스토어 | Play 스토어 사용 가능 + 앱이 스토어에 등록 | ✗ Play 스토어 사용 불가 |
| ADB 사이드로딩 (개발자 모드 불필요, Chrome 81+) | 설정 → Linux 개발 환경 켜기 → "Android 앱 개발" → ADB 디버깅 켜기 → `adb install` | ✗ Linux 개발 환경 사용 불가 |
| 개발자 모드 | 기기 초기화(Powerwash) 후 개발자 모드 진입 | ✗ 관리(학교) 기기는 정책상 차단되는 것이 일반적이며, 우회 시도는 하지 않습니다 |
| 관리자 배포 | Google 관리 콘솔에서 Android 앱 허용/강제 설치(관리형 Google Play) 또는 사이드로딩 허용 정책 | △ 관리자 결정 사항 |

- 공식 문서: Android 개발자 문서 「Prepare the development environment」 — *"Since Chrome 81, developers can keep their devices out of developer mode and still deploy apps"*, 단 **Linux를 켜고 "Develop Android apps → Enable ADB debugging"** 을 거쳐야 합니다.
- 관리 기기에는 ARC 사이드로딩 허용 여부를 정하는 기기 정책이 있습니다(2018년 Chromium 엔터프라이즈 정책 추가). 따라서 학교 기기에서의 설치 가능 여부는 **관리자 정책이 결정**합니다.
- "Play 스토어 사용 불가"가 **Android 앱 기능 자체가 꺼져 있다**는 뜻이라면(설정 → 앱에 Google Play 스토어 항목이 없거나 꺼져 있음), APK를 어떤 방법으로 옮겨 와도 **실행할 런타임이 없습니다.**

**→ 판단:** 사용자 Chromebook에서 APK 설치는 "확인 필요"가 아니라 **"현재 조건에서는 불가, 관리자 승인 또는 다른 기기 필요"** 로 기록합니다. 설치 차단을 우회하는 방법(개발자 모드 강제 전환, 정책 해제, 원격 프록시 등)은 제공하지 않습니다.

### 각 후보에 대한 판단 근거

**A. Kotlin + Android WebView (채택)**
- WebView 데이터(쿠키, localStorage, IndexedDB, HTTP 캐시)는 앱의 개인 데이터 디렉터리(`app_webview`, `cache`)에 저장되고, 방문 기록·북마크는 앱 전용 SQLite(`databases/browser.db`)에 저장됩니다. ChromeOS의 Chrome은 이 디렉터리를 읽을 수 없고, 이 앱도 Chrome 데이터를 읽지 않습니다.
- 엔진은 OS가 업데이트하는 Android System WebView(Chromium)이므로 사이트 호환성과 보안 패치를 직접 관리할 필요가 없습니다.
- 단점은 설치 경로뿐입니다(2장).

**B. Chromium 기반 다른 독립 브라우저 앱**
- Chromium을 직접 포함하는 앱(예: Chromium/Cromite 포크, GeckoView 기반 앱)도 결국 **APK**이므로 2장의 설치 장벽이 똑같이 적용됩니다.
- 엔진 빌드는 GitHub 기본 러너의 디스크·시간 제한을 넘기 쉽고, 보안 패치를 매달 따라가야 합니다. A 대비 얻는 것이 없어 보류했습니다.

**C. 원격 브라우저(서버에서 엔진 실행)**
- 기록 분리 측면에선 동작하지만, (1) 서버 비용과 상시 운영, (2) 로그인 세션·비밀번호가 서버에 저장되는 보안 책임, (3) 학교 네트워크 필터를 거치지 않고 웹에 접속하게 되는 **정책 우회 도구**라는 문제가 있습니다. 요구사항("학교 정책을 우회하지 않는다")에 어긋나므로 기각했습니다.

**D. 웹 기반 대안**
- HTML 페이지, PWA, Chrome 확장 프로그램은 모두 Chrome 프로필 안에서 동작하므로 쿠키·기록이 Chrome과 분리되지 않습니다.
- ChromeOS의 Isolated Web App(IWA) + Controlled Frame은 별도 저장소 파티션을 쓸 수 있지만, **관리자 강제 설치 정책(IsolatedWebAppInstallForceList)이나 개발자 플래그**가 있어야 설치됩니다. 즉 A와 마찬가지로 관리자 승인이 필요하고, 일반 사용자가 HTML 파일로 대신할 수 없습니다.
- 그래서 웹 기술은 **"다운로드·실행 도우미"** 로만 사용합니다(`launcher/IndependentBrowser-Launcher.html`). 이 파일은 스스로 브라우저라고 주장하지 않습니다.

## 4. 배포 방식 선택

| 산출물 | 형식 | 이유 |
|---|---|---|
| 실제 브라우저 | `IndependentBrowser.apk` (GitHub Releases) | ChromeOS가 지원하는 Android 앱 형식. 네이티브 코드가 없어 Intel/AMD/ARM Chromebook 모두 같은 APK 사용 |
| 클릭 실행 도우미 | `IndependentBrowser-Launcher.html` | ChromeOS 파일 앱에서 클릭하면 Chrome으로 열림(지원 형식). APK 다운로드 링크, 설치된 앱 열기 버튼, 안내 문서 링크 제공. 자동 다운로드·자동 실행 없음 |
| 설치 후 실행 | ChromeOS 런처/선반 아이콘 | 설치된 Android 앱의 정식 실행 경로 |
| 설치 후 파일 클릭 실행 | 파일 앱에서 `.html` 파일 → "연결 프로그램: 독립 브라우저" | 앱이 `text/html` VIEW 인텐트를 등록해 ChromeOS 파일 앱의 "열기" 목록에 나타남 |

`.url`/`.desktop` 같은 바로가기 파일은 ChromeOS 파일 앱이 앱 실행 수단으로 지원하지 않으므로 사용하지 않았습니다.

## 5. 이 앱이 하지 않는 것 / 할 수 없는 것

- Google 계정 '내 활동', 검색 기록 등 **웹사이트 서버에 저장되는 기록**은 삭제·차단할 수 없습니다.
- 학교·회사 관리자, 네트워크 장비, 인터넷 사업자가 남기는 접속 기록은 이 앱과 무관합니다.
- Google은 2021년부터 **임베디드 WebView에서의 Google OAuth 로그인**을 `disallowed_useragent` 오류로 차단합니다. 이 앱은 그 제한을 우회하도록 User-Agent를 위장하지 않습니다(데스크톱 모드에서도 `wv` 표시 유지). Google 계정 로그인이 필요한 사이트는 실패할 수 있습니다.
- 인증서 오류가 있는 사이트는 "그래도 계속" 없이 항상 차단합니다.
