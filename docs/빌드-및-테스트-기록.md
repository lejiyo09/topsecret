### 미해결 사항: run #5의 API 34 실행 실패
- v1.0.1 코드로 3번 실행(#4, #5, #6) 중 **1번(#5, API 34)** 릴리스 APK 스모크 테스트가 실패했습니다. 실행 20초 뒤 프로세스가 없었고 화면은 홈 화면이었으며, 크래시 버퍼에는 이 앱 기록이 없었습니다.
- 당시에는 실행 결과·프로세스 추적 로그를 남기지 않아 **원인을 확인하지 못했습니다.** 앱이 조용히 종료된 것인지, 에뮬레이터 측 문제인지 단정할 수 없습니다.
- 이후 실행부터는 `am-start-api*.txt`, `pid-trace-api*.txt`, `logcat-release-excerpt-api*.txt`가 보고서에 남으므로, 다시 발생하면 원인을 추적할 수 있습니다.

### run #3에서 발견한 버그와 수정 (v1.0.0에 포함된 결함)

- **증상**: 인증서가 잘못된 사이트에 접속하면 연결은 항상 차단되지만, 이전 페이지가 아직 로딩 중일 때 주소를 입력하면 "보안 오류" 안내 페이지가 표시되지 않고 빈 화면이 될 수 있었습니다. (보안상 차단은 유지되었고, 안내 표시만 누락)
- **원인**: 이전 페이지(시작 시 열린 Google 홈)의 `onPageStarted/onPageFinished`가 늦게 도착하면서 새로 요청한 주소(`pendingUrl`)를 지워, 인증서 오류를 하위 리소스 오류로 잘못 분류했습니다.
- **근거**: 수정 후 API 34 로그 — 오류 시점에 `view=https://www.google.com/ tab=https://www.google.com/`였고, 요청 주소(`pending=https://expired.badssl.com/`)로만 메인 페이지 오류임을 식별할 수 있었습니다.
- **수정**: `pendingUrl`은 그 주소의 페이지가 시작/완료될 때만 해제하고 60초 후 만료. URL 비교 함수 `UrlInput.sameDocument`와 단위 테스트 추가.
- **조치**: v1.0.1을 사용하세요. `releases/latest` 링크는 v1.0.1을 가리킵니다.

> 이 저장소를 만든 클라우드 작업 환경에서는 Google Maven(`dl.google.com`)이 네트워크 정책으로 막혀 있어 로컬 빌드를 할 수 없었습니다.
> 그래서 첫 컴파일 검증이 CI(run #1)에서 이루어졌고, 실패한 기록도 그대로 남겼습니다.

계측 테스트 10개가 검증한 내용:
1. 앱 시작 시 탭 1개
2. 주소창에 `example.com` 입력 → `https://example.com/` 실제 로딩
3. 방문한 페이지가 앱 자체 방문 기록 DB에 저장됨
4. 검색어 입력 → 검색 엔진(Google)으로 이동
5. Ctrl+T / Ctrl+W / Ctrl+Tab 단축키로 탭 열기·닫기·전환, 일반 키 입력은 가로채지 않음
6. 마지막 탭을 닫으면 빈 탭 1개 유지
7. **인증서 만료 사이트(`expired.badssl.com`) 차단**, 차단된 페이지는 방문 기록에 남지 않음
8. 북마크·방문 기록 저장/중복 처리/삭제
9. **데이터 삭제 시 쿠키 제거** 확인
10. WebView 데이터 디렉터리가 **앱 전용 샌드박스**(`/data/data/<패키지>/app_webview`)에 생성됨

### 참고 사항 (있는 그대로)
- API 34 스모크 테스트 스크린샷에 "Pixel Launcher isn't responding" 대화상자가 보입니다. 이것은 에뮬레이터의 **홈 화면 앱(Pixel Launcher)** 이 느린 CI 에뮬레이터에서 응답 지연된 것이며, 그 뒤에 독립 브라우저가 example.com을 정상 표시하고 있습니다. 앱의 크래시 버퍼에는 이 앱 관련 기록이 없습니다.
- API 30 에뮬레이터의 WebView는 83 버전으로 오래되었습니다. 실제 Chromebook은 ChromeOS 업데이트와 함께 최신 WebView를 받습니다.

## 검증하지 못한 것

- **실제 Chromebook에서의 설치·실행**: CI에는 ChromeOS 기기가 없어 검증하지 못했습니다. 에뮬레이터는 같은 Android 버전·큰 화면·x86_64 환경이지만 ChromeOS의 창 관리(ARC), 파일 앱 연동, 관리 정책은 재현하지 않습니다. → [설치 가이드](설치-가이드.md)의 점검표로 직접 확인이 필요합니다.
- **사용자 Chromebook에서의 설치 가능성**: Play 스토어·Linux가 모두 막힌 환경에서는 설치 경로가 없습니다([기술 선택 보고서](기술-선택-보고서.md) 2장).
- 파일 업로드 선택창, 카메라/마이크 권한, 전체 화면 동영상, 다운로드 실제 저장은 자동 테스트에 포함되지 않았습니다(코드 구현만 됨).
